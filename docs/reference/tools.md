# Tool reference

> **Note.** This page is hand-maintained in this release (the internal
> `scripts/build_mkdocs.py` generator that regenerated it from a live stdio
> session is not part of this export). If a tool's name, tier, or arguments
> change, update this page too.

All **101** tools the server registers, grouped by module. Arguments in **bold** are required.

## Risk tiers

The tier determines the gate, so a tool cannot forget to check.

| Tier | Gate | Meaning |
|---|---|---|
| read | none | Cannot change anything. |
| low | none | Trivially reversible — lights, beeps, fan speed. |
| motion | `confirm=true` | Moves the machine. |
| thermal | `confirm=true` | Applies heat. |
| print | token | Starts or ends a print job. |
| destructive | token | Irreversible: deletes data, rewrites config, restarts firmware. |
| emergency | **never gated** | `emergency_stop`. Works in read-only mode. |

A *token* is a two-step `confirm_token` bound to the exact arguments, single-use, expiring in 120 s. See the [safety model](safety-model.md).

The **Risk** column shows the highest tier a tool can reach. Ten tools pick a lower tier for some arguments (`set_temperature` is `low` for a target of 0; `run_gcode` is `read` for a pure query).

## Status & telemetry

Read the machine: readiness, temperatures, position, progress, logs. Every tool here is read-only and needs no confirmation.

| Tool | Risk | What it does | Arguments |
|---|---|---|---|
| `get_audit_log` | **read** | Every non-read action this MCP server has taken on the printer this session, with risk tier, arguments, and outcome (including refusals). Use it to answer 'what did the agent actually do to my printer?' | `count` <small>integer</small> |
| `get_capabilities` | **read** | What this specific printer supports, discovered live: heaters and their real temperature limits, controllable fans, sensors, LEDs, output pins, filament sensors, axis travel, calibration features, QIDI-specific Klipper modules, Moonraker components present, and macro count. Call this before assuming a feature exists — QIDI ship a trimmed Moonraker and an extended Klipper. | `refresh` <small>boolean</small> |
| `get_gcode_log` | **read** | Recent G-code console history — the commands sent and Klipper's replies, exactly what the Fluidd console shows. The fastest way to see why something failed or what a macro actually did. | `count` <small>integer</small> |
| `get_job_status` | **read** | Detail on the current print job: state, filename, progress by both layer and file position, durations, filament used, estimated remaining time, and the slicer metadata for the running file. | — |
| `get_position` | **read** | Toolhead position: raw kinematic position, the G-code position (offsets applied), which axes are homed, the active Z offset, and speed/flow factors. | — |
| `get_printer_config` | **read** | The printer's live Klipper configuration as Moonraker reports it: either the resolved settings tree (section -> key -> value) or the list of section names. Pass a section name to get just that section — the full tree is large. | `section` <small>any</small><br>`list_sections` <small>boolean</small> |
| `get_printer_status` | **read** | Overall printer state: Klipper readiness, print job state and progress, temperatures, position, homed axes, and any active error message. Start here — this is the cheapest complete picture of the machine. | — |
| `get_safety_policy` | **read** | The safety envelope this MCP server is enforcing: temperature ceilings, confirmation thresholds, jog/extrude caps, read-only and during-print flags, and which risk tiers require confirmation. Read this to understand why a call was refused. | — |
| `get_system_info` | **read** | Host and service health: Moonraker/Klipper versions, the printer's OS and CPU, load, memory, uptime, throttle flags (undervoltage), MCU load and communication error counters. Use this when prints fail oddly — an undervoltage flag or MCU bandwidth saturation explains a lot. | — |
| `get_temperature_history` | **read** | Moonraker's cached temperature history (roughly the last 20 minutes, 1 Hz) for every heater and sensor: temperatures, targets, and power. Use this to judge whether a heater is tracking its target or a thermal runaway is developing. | `sensor` <small>any</small><br>`last_n` <small>integer</small><br>`include_monitors` <small>boolean</small> |
| `get_temperatures` | **read** | Current temperature, target, and heater power for every heater, plus all read-only temperature sensors (including the Max4's chamber thermal-protection sensor) and temperature-controlled fans. | — |
| `list_gcode_commands` | **read** | Every G-code command and macro this printer accepts, with descriptions where available. Includes QIDI's custom macros (PRINT_START, M4029 levelling, M603/M604 filament handling, CLEAR_NOZZLE, and so on). Filter with `contains`. | `contains` <small>any</small><br>`limit` <small>integer</small> |
| `query_objects` | **read** | Escape hatch for arbitrary Klipper status objects. Pass a list of object names (e.g. ['bed_mesh','probe','mcu']); omit to get the full object list instead. Use get_capabilities first to see what exists. | `objects` <small>any</small> |

## Heaters

Set and wait on temperatures. Targets are checked against the envelope before anything is sent; turning a heater <em>off</em> is never refused.

| Tool | Risk | What it does | Arguments |
|---|---|---|---|
| `wait_for_temperature` | **read** | Poll until a heater reaches its target (within tolerance) or the timeout expires. Does not change any target — set_temperature does that. Safe to call repeatedly; returns the temperature trend so you can tell whether heating is actually progressing. | **`heater`** <small>string</small><br>`target` <small>any</small><br>`tolerance` <small>number</small><br>`timeout_s` <small>number</small> |
| `cooldown` | **low** | Turn off every heater (extruder, bed, chamber) in one call. Always permitted — this is the safe direction — and the right thing to call when you are unsure of the machine's state or finishing a session. The QIDI Box's own heater (filament drying) is left alone unless also_box_heater=true, so a drying run is not ended by accident. | `also_stop_fans` <small>boolean</small><br>`also_box_heater` <small>boolean</small> |
| `set_temperature` | **destructive** | Set a heater's target temperature. heater is 'extruder', 'bed', or 'chamber'; target is °C (0 turns the heater off). Returns immediately — the printer heats in the background; use wait_for_temperature to block until it arrives. Requires confirm=true. Refused if the target is outside the safety envelope, and while a print is running unless the server allows it. | **`heater`** <small>string</small><br>**`target`** <small>number</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |

## Motion

Homing, jogging, absolute moves, extrusion, speed and Z offset. Blocked during a print, and gated on the axis being homed.

| Tool | Risk | What it does | Arguments |
|---|---|---|---|
| `extrude_filament` | **motion** | Manually extrude (positive) or retract (negative) filament, in mm. The hotend must already be at or above Klipper's min_extrude_temp (135 °C on the Max4) — heat it with set_temperature first. Capped per call by policy. Requires confirm=true. Blocked during a print. | **`distance`** <small>number</small><br>`feedrate` <small>number</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `home_axes` | **motion** | Home the printer. Omit axes to home all of them (G28), or pass e.g. 'xy' to home a subset. On the Max4, homing Z runs the inductive probe against the bed. Requires confirm=true. Blocked during a print. | `axes` <small>any</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `motors_off` | **motion** | Disable the stepper motors (M84). The toolhead can then be moved by hand, but the printer loses its homed position and must be re-homed. Refused while a print is running — it would abandon the job mid-air. | `confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `move_absolute` | **motion** | Move the toolhead to absolute coordinates in mm. Supply any of x/y/z; omitted axes hold position. feedrate is mm/min (capped by policy). Axes must be homed and each coordinate must be inside the machine's travel. Requires confirm=true. Blocked during a print. | `x` <small>any</small><br>`y` <small>any</small><br>`z` <small>any</small><br>`feedrate` <small>number</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `move_relative` | **motion** | Jog the toolhead by a relative offset in mm (any of dx/dy/dz). The destination is computed and bounds-checked before moving, and a single jog is capped by policy. Requires confirm=true. Blocked during a print. | `dx` <small>number</small><br>`dy` <small>number</small><br>`dz` <small>number</small><br>`feedrate` <small>number</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `set_flow_factor` | **motion** | Set the extrusion flow override (M221) as a percentage, 50–150. Applies live. Use sparingly — flow changes mid-print show up as a visible band. | **`percent`** <small>number</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `set_speed_factor` | **motion** | Set the print speed override (M220) as a percentage, 10–200. Applies live to a running print. Slowing a print that is having quality trouble is a common fix. | **`percent`** <small>number</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `set_z_offset` | **motion** | Adjust the live Z offset (baby-stepping), in mm — positive raises the nozzle. Use mode='adjust' to nudge relative to the current offset, or mode='set' for an absolute value. Applies immediately, including mid-print, which is the usual way to fix first-layer squish. Not persistent across restarts. | **`offset`** <small>number</small><br>`mode` <small>string</small><br>`move` <small>boolean</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |

## Print jobs

Start, pause, resume and cancel prints; inspect the queue and history. Starting a print binds the file's size and mtime into the token.

| Tool | Risk | What it does | Arguments |
|---|---|---|---|
| `check_print_fit` | **read** | Before printing or queueing: does what the QIDI Box records in its slots suit these files? Compares each file's filament type and colours (from its slicer metadata) with the material and colour recorded per slot, and says which slots could serve each one. Names may be loose ('benchy'); an ambiguous or unknown name is an error that lists candidates. Advisory only: it never blocks, and it does not claim to know which slot the printer feeds for which tool. Returns nothing to compare on a printer with no Box. | **`filenames`** <small>array</small> |
| `get_history_totals` | **read** | Lifetime totals for the machine: jobs completed, total print time, longest job, and total filament used. | — |
| `get_job_queue` | **read** | The pending job queue: what is lined up to print next and whether the queue is started or paused. | — |
| `get_print_history` | **read** | Past print jobs with status, duration, filament used and timestamps. Useful for 'did the last print succeed?' and for spotting a pattern of failures. | `limit` <small>integer</small><br>`start` <small>integer</small> |
| `control_job_queue` | **print** | Start or pause the shared job queue. action='start' releases it so queued jobs begin printing as soon as the printer is idle — that needs the printer lease, since it commits the machine. action='pause' holds them, which is always allowed: preventing surprise starts is the safe direction. Requires confirm=true. Neither affects a job that is already printing. | **`action`** <small>string</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `pause_print` | **print** | Pause the running print. On the Max4 this runs QIDI's PAUSE macro, which parks the toolhead and retracts. Requires confirm=true and an active print. | `confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `queue_jobs` | **print** | Add one or more G-code files to the shared print queue. Names may be loose ('benchy' finds benchy.gcode); an unknown or ambiguous name fails the whole call with the candidates. The first call (no confirm) shows what each name resolved to, its print time, and whether the Box's filament suits it; re-call with confirm=true to queue. This is the cooperative way to share the machine: when somebody else is printing, queue your file so it runs after theirs instead of competing for the printer. Requires confirm=true. If the queue is already 'ready' it auto-starts when the printer goes idle, so in that state this counts as starting a print and also needs the printer lease. | **`filenames`** <small>array</small><br>`reset` <small>boolean</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `remove_queued_jobs` | **print** | Remove jobs from the print queue by job_id, or clear the whole queue with all=true. Requires confirm=true. | `job_ids` <small>any</small><br>`all` <small>boolean</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `resume_print` | **print** | Resume a paused print. Requires confirm=true and a paused job. | `confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `cancel_print` | **destructive** | Cancel the running or paused print. This ruins the part — the job cannot be resumed afterwards. Two-step confirmation, and it reports how far along the print was so you can see what you are throwing away. | `confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `start_print` | **destructive** | Start printing a G-code file already on the printer (path relative to the gcodes root, e.g. 'benchy.gcode' or 'projects/bracket.gcode'). Two-step confirmation: the first call returns the file's slicer metadata plus a token so you can check you are printing the right thing, and the second call with that token starts it. Refused if a job is already running. | **`filename`** <small>string</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |

## Files

List, upload, download, move, copy and delete G-code. Overwriting an existing file is treated as destructive, because it is not reversible.

| Tool | Risk | What it does | Arguments |
|---|---|---|---|

Use tail=true to read the end. | **`path`** <small>string</small><br>`root` <small>string</small><br>`max_bytes` <small>any</small><br>`tail` <small>boolean</small> |
| `get_file_metadata` | **read** | Full slicer metadata for one G-code file: estimated time, filament length and weight, layer heights, per-object height, nozzle diameter, filament type, first-layer and chamber temperatures, thumbnails present, and the slicer used. Read this before start_print to confirm the file matches the loaded filament. | **`filename`** <small>string</small> |
| `list_directory` | **read** | List one directory's immediate contents (subdirectories and files) under a root. Use this instead of list_gcode_files when you care about folder structure. | `path` <small>string</small><br>`extended` <small>boolean</small> |
| `list_file_roots` | **read** | The file roots this printer exposes (gcodes, config, logs, timelapse) with their permissions. Tells you where you may read and write. | — |
| `list_gcode_files` | **read** | List G-code files on the printer with size, modified time, and (when scanned) estimated print time and filament use. | `delete_directory` | **destructive** | Delete a directory on the printer. | `move_file` | **destructive** | Move or rename a file/directory on the printer. Both paths include the root, e.g. source='gcodes/old.gcode', dest='gcodes/archive/new.gcode'. Requires confirm=true. | **`source`** <small>string</small><br>**`dest`** <small>string</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `upload_gcode` | **destructive** | Upload a G-code file to the printer. Provide the content either as `content` (plain text) or `content_base64` (for binary-safe transfer). Does NOT start a print — call start_print separately, deliberately. Requires confirm=true; set overwrite=true to replace an existing file. | **`filename`** <small>string</small><br>`content` <small>any</small><br>`content_base64` <small>any</small><br>`subdirectory` <small>string</small><br>`overwrite` <small>boolean</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |

## Calibration

Bed mesh, Z tilt, probe accuracy, screw tilt, input shaper and resonance testing. These move the machine unattended for minutes.

| Tool | Risk | What it does | Arguments |
|---|---|---|---|
| `get_bed_mesh` | **read** | The active bed mesh and saved profiles: the probed Z deviation grid, its range, and the mesh area. Reveals whether the bed is warped and by how much. | `include_matrix` <small>boolean</small> |
| `query_endstops` | **read** | Read every endstop's triggered/open state without moving. Use this to diagnose a homing failure — a switch already reading 'TRIGGERED' at rest is the usual culprit. | — |
| `query_probe` | **read** | Read the probe's current state (triggered or open) without moving anything. On the Max4 this is QIDI's inductive 'probe_air' sensor. | — |
| `probe_accuracy` | **motion** | Probe the same point repeatedly and report min/max/average/median/stddev. This is the diagnostic for 'is my probe repeatable?' — a stddev above ~0.01 mm means the probe or gantry has a mechanical problem. Moves Z only. Requires confirm=true. | `samples` <small>integer</small><br>`probe_speed` <small>any</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `screws_tilt_calculate` | **motion** | Probe the bed's screw positions and report how far, and which way, to turn each levelling knob. The Max4 has four screws. Manual bed levelling aid — the printer only measures; you turn the knobs. Requires confirm=true. | `direction` <small>any</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `set_input_shaper` | **motion** | Set input shaper frequency/type directly, without running a calibration sweep. Useful to apply values you already know. Applies in memory only. | `freq_x` <small>any</small><br>`freq_y` <small>any</small><br>`shaper_type_x` <small>any</small><br>`shaper_type_y` <small>any</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `z_tilt_adjust` | **motion** | Level the Max4's two independent Z steppers against each other (Z_TILT_ADJUST). Probes the configured points and adjusts each Z motor until the gantry is square. Run this if first layers are thicker on one side. Requires confirm=true. | `retries` <small>any</small><br>`retry_tolerance` <small>any</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `bed_mesh_calibrate` | **destructive** | Probe the bed and build a new mesh. Takes several minutes on the Max4's 9x9 grid and moves the toolhead across the whole bed; the bed should be at printing temperature for a meaningful result. The mesh is active immediately but NOT saved to disk — use bed_mesh_profile to save it. Two-step confirmation. | `profile` <small>any</small><br>`adaptive` <small>boolean</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `bed_mesh_profile` | **destructive** | Manage bed mesh profiles: action='load' to apply a saved profile, 'save' to persist the current mesh (this writes printer.cfg and RESTARTS Klipper), 'remove' to delete one, or 'clear' to drop the active mesh. Save/remove are two-step because they rewrite the config. | **`action`** <small>string</small><br>`name` <small>any</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |
| `input_shaper_calibrate` | **destructive** | Run resonance testing with the toolhead accelerometer and compute optimal input shaper settings (SHAPER_CALIBRATE). The gantry is shaken hard through a frequency sweep — loud, and it must not be interrupted. Results are applied in memory; saving them rewrites printer.cfg. Two-step confirmation. Note: the Max4 also ships QIDI's own M901 macro for this. | `axis` <small>any</small><br>`confirm` <small>boolean</small><br>`confirm_token` <small>any</small> |

## Camera

| Tool | Risk | What it does | Arguments |
|---|---|---|---|
| `get_webcam_snapshot` | **read** | Grab a still image from the printer's camera and return it for inspection. ## QIDI-specific

Vendor features with no upstream equivalent: staged filament load/unload, chamber control, the AMS box, nozzle cleaning, soft aborts, power-loss resume.

| Tool | Risk | What it does | Arguments |
|---|---|---|---|
| `get_ai_detection_status` | **read** | Report the Max4's AI failure detection: whether spaghetti ('noodle') and foreign-object detection are enabled, their sensitivity, and the last verdict the camera service reported. Read-only. Note a zero count from a DISABLED detector means 'nothing ever reported', not 'the bed is clear' -- check the enabled flags before trusting it as evidence of anything. | — |
| `get_box_status` | **read** | State of QIDI's Box (the multi-filament switcher): whether the firmware will actually use it, each unit's four slots with what the printer believes is in them (filament, colour and vendor decoded to names where QIDI's tables are readable), which slot is synced to the extruder, and the live box_extras object verbatim. If the Box is not working, `problems` says which of the conditions QIDI's macros test is false. Compare `slots` with the file's filament_type / filament_colors / referenced_tools from get_file_metadata before printing a multi-colour job. Returns box_count=0 on a machine with no Box. | — |

## Sharing the printer

The cooperative lease that stops two agents driving one machine at once. Stored on the printer itself, so every agent sees the same claim; <em>cooperative</em>, because the touchscreen and Fluidd ignore it.

| Tool | Risk | What it does | Arguments |
|---|---|---|---|
| `get_printer_lease` | **read** | Who is currently driving this printer, if anyone. Returns the holder's name, their stated reason, and how many minutes are left, plus whether it is you. A print started at the touchscreen or from Fluidd shows as a manual-print claim (manual=true) held by nobody. Call this first when a write is refused with 'lease_held', and before starting any long job. Reports coordination as unavailable on a printer whose Moonraker has no database component. | — |
| `acquire_printer_lease` | **low** | Claim this printer for yourself, so other agents are refused mutating actions while you work. Give a short human reason ('bracket v3, ~40 min') — the point is that whoever gets blocked can see who to talk to. Refused if somebody else holds it. Expires on its own so a forgotten lease cannot strand the machine; renew it with renew_printer_lease for long jobs. This is cooperative: it does not stop the printer's own touchscreen or Fluidd. | `reason` <small>string</small><br>`minutes` <small>any</small><br>`confirm` <small>boolean</small> |
| `release_printer_lease` | **low** | Give the printer back when you are finished. Do this rather than letting the lease expire — the next person should not have to wait out your timeout. | — |
| `renew_printer_lease` | **low** | Extend your own lease, for a job that is taking longer than planned. Refused if you do not hold it, or if it already lapsed and somebody else took it. | `minutes` <small>any</small> |
| `break_printer_lease` | **destructive** | Force-release SOMEBODY ELSE's lease, for when its holder has clearly gone away and the machine is stranded. Two-step confirmation, and the break is recorded in the audit log with your name. Check get_printer_lease and look at the machine first: if a print is actually running, breaking the lease does not stop it, and cancel_print or emergency_stop is what you want. On a manual-print claim (a print started at the touchscreen, shown with manual=true) this takes the print over: the claim becomes yours so you can then pause or cancel it. | `why` <small>string</small><br>`confirm_token` <small>any</small> |

## System & escape hatches

Service and host control, raw G-code and macros. The raw path is screened against the deny-list <em>and</em> the numeric envelope.

| Tool | Risk | What it does | Arguments |
|---|---|---|---|
| `get_klipper_log` | **read** | Read the tail of klippy.log — the definitive place to find why Klipper shut down, what an MCU error was, or what a failed print reported. Truncated to a byte budget. | `max_bytes` <small>integer</small><br>`which` <small>string</small> |
| `abort_heating` | **low** | Abort a heater WAIT that is blocking the queue (QIDI's breakheater). | `abort_macro` | **motion** | Abort a running macro (QIDI's breakmacro).
